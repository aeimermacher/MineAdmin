# MineAdmin

MineAdmin is a self-hosted dashboard for monitoring and managing Bitaxe miners running AxeOS. It polls miners over HTTP and serves a browser-based dashboard from a small Node.js server.

## Features

- Live miner status, hashrate, power, efficiency, temperatures, fan speed, shares, uptime, pool, and firmware information.
- Six-hour hashrate, power, and efficiency charts.
- Optional NiceHash earnings, worker, and payout information.
- Add or remove miners, identify a miner, restart it, or apply settings to one or several miners.
- Password-protected changes, with monitoring available without logging in.

## Requirements

- Node.js 18 or later.
- Network access from the server to each miner's AxeOS HTTP API.
- NiceHash API credentials only if you want to display NiceHash information.

There are no external Node.js package dependencies to install.

## Quick Start

1. Create the local configuration file from the example.

   PowerShell:

   ```powershell
   Copy-Item config.example.json config.json
   ```

   macOS/Linux:

   ```sh
   cp config.example.json config.json
   ```

2. Edit `config.json`. Add your miners' IP addresses or hostnames, and choose a `host` and `port` for the dashboard. Use `127.0.0.1` for access from the server itself, or `0.0.0.0` to listen on all IPv4 interfaces so other devices on your network can connect. Allow the selected port through your firewall as needed.

3. Set the administrator password:

   ```sh
   npm run set-password
   ```

   Enter and confirm a password of at least eight characters. The password is stored as a scrypt hash in `config.json`.

4. Start the server:

   ```sh
   npm start
   ```

5. Open `http://127.0.0.1:8080` in a browser, adjusting the address and port to match your configuration.

## Configuration

`config.example.json` documents the available settings. The server reads `config.json` from the project directory at startup.

| Setting | Description |
| --- | --- |
| `host` | Network interface address for the HTTP server. Use `127.0.0.1` for local-only access or `0.0.0.0` to listen on all IPv4 interfaces. |
| `port` | HTTP server port. |
| `pollIntervalSeconds` | How often the server polls miners and records dashboard history. |
| `requestTimeoutMs` | Timeout for an individual miner request. |
| `limits.frequency` | Allowed minimum and maximum frequency values, in MHz, for settings updates. |
| `limits.coreVoltage` | Allowed minimum and maximum core voltage values, in mV, for settings updates. |
| `nicehash` | Optional API key, secret, organization ID, display currency, and polling interval. Leave credentials blank to disable the integration. |
| `miners` | Initial list of miners, each with a `name` and IP address or hostname in `ip`. |
| `auth.passwordHash` | Generated by `npm run set-password`; do not enter a plaintext password here. |

Miner additions and removals made in the dashboard are saved to `config.json`. The server re-reads the file before saving the miner list so other configuration values are preserved.

### NiceHash

To enable NiceHash information, create an API key with the read-only **Mining / View mining data and statistics** permission. Add the key, secret, and organization ID under `nicehash` in `config.json`, then restart MineAdmin. NiceHash polling runs at the configured interval, with a minimum interval of 30 seconds.

## Using the Dashboard

The dashboard continues monitoring without a login. Log in to add or remove miners, change miner settings, identify miners, or restart them. You can select multiple miners to apply supported settings or restart them together. A manual refresh polls all configured miners immediately.

Settings include hostname, frequency, core voltage, fan mode and speed, and Stratum pool connection fields. The configured frequency and voltage limits are enforced by the server. Bulk Stratum usernames have each miner's hostname appended to distinguish workers.

## Security Notes

- `config.json` is excluded by `.gitignore`; keep API secrets and password hashes out of source control and backups that are shared publicly.
- The dashboard uses plain HTTP and is intended for a trusted network. Do not expose it directly to the public internet; use an appropriately secured network or reverse proxy if remote access is required.
- Logging in protects changes, but monitoring endpoints are available without authentication and include miner details. Restrict network access accordingly.
- Changing the configured administrator password does not immediately invalidate existing sessions; sessions expire after 12 hours.
